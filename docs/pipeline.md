# 从 47.5 mm Marker 到实时 6DoF 轨迹

本文是本项目的完整开发链路。所有位姿采用齐次变换 `T_A_B` 表示“把 B 坐标系中的点变换到 A 坐标系”。长度统一使用米。

## 1. 物理标记与相机输入

夹爪刚性主体上安装多个 ArUco 面标记。当前黑色方框外边长实测为 47.5 mm；代码和 rig 标定都使用这个尺寸。必须量黑色方框外边长，而不是白纸裁切边。可动夹指上的标记不能直接和主体标记放入同一个刚体模型。

D455 输出彩色图像、设备时间戳和相机内参。录制程序保存 `poses.csv`、`frames.csv`、`metadata.json` 和可选原始 `.db3`，因此离线回放可以复现同一输入。D455 的畸变投影通过 RealSense SDK 完成，避免把设备模型误当作普通针孔相机。

T265 不提供 RGB/深度，而是输出同步的 `848x800 Y8` 左右鱼眼、IMU 和 pose stream。`t265.py` 使用 SDK 的 Kannala-Brandt4 鱼眼内参和左右外参；两只鱼眼分别经过同一 `RigTracker`，右眼位姿转换到左眼坐标系后再做 80 mm / 12° 一致性门控和融合。ROS 2 bag 的回放入口与输入要求见 [Sensor bag 回放](sensor_bag_replay.md)。

## 2. ArUco 检测和角点

每帧先转灰度，使用配置的 OpenCV 字典（默认 `DICT_4X4_50`）检测 Marker。检测到的四角按左上、右上、右下、左下顺序保存，并使用 `CORNER_REFINE_SUBPIX` 做亚像素细化。帧边缘附近、边长过小或重复 ID 的观测在后续门控阶段被拒绝。

输出的每个单面观测包含 ID、像素角点、单面平移/旋转和重投影误差。单面结果用于初始化和降级路径，不把多个独立单面位姿直接平均。

## 3. 单面 IPPE/PnP

对平面四角，先用 `solvePnPGeneric(..., SOLVEPNP_IPPE_SQUARE)` 产生两个平面候选解。保留所有角点在相机前方且重投影误差较小的候选。IPPE 显式给出歧义候选，并不保证仅靠 RGB 重投影就能选出真实分支；单面状态在页面中明确标成 `SINGLE`。

离线核心包对一张图像也支持 `solvePnPRansac(EPNP) + solvePnPRefineLM`：当多个面的三维角点已经注册到同一刚体坐标系时，所有角点一次联合求解，得到更稳定的 `T_camera_gripper`。

## 4. 多面刚体标定

通过一段包含面与面重叠可见的录制，计算每一对 Marker 的固定关系：

```text
T_tag_i_tag_j = inverse(T_camera_tag_i) · T_camera_tag_j
```

对每条重叠边使用中位数平移、四元数平均和离群点剔除。只有重叠帧数达到 `--min-overlap` 且关系边有足够内点时才接受。以参考 ID 2 做 BFS 初始化，再用邻接边迭代平均改善闭环一致性；这不是角点级全局 bundle adjustment。不连通的 Tag 不会被伪造为已标定。

## 5. 联合角点位姿

实时阶段把每个 Tag 的局部四角通过 `T_reference_tag` 变换到同一个刚体坐标系：

```text
P_body(tag) = T_reference_tag · P_tag
```

每个当前可见面先用 IPPE 产生刚体位姿候选，再把候选放入同一 `solvePnP(ITERATIVE)` 精修。对全部当前面计算每面重投影误差；坏面被剔除后再次精修。最终选择“支持面数量最多、误差最小”的假设：多于一个面为 `MULTI`，只有一个面为 `SINGLE`。

## 6. 时序门控和分段

D455 的可选 `--use-depth` 插在联合 PnP 与最终时序门控之间。原始深度点云通过
真实 `T_color_depth` 外参变换后，按 RGB Marker 内缩 ROI 提取；先排除与 RGB
预测面明显不符的深度，再逐面 RANSAC + SVD 拟合并检查内点率、残差和覆盖率。
`rgbd.py` 将 RGB 重投影和点到面残差按噪声尺度、点数归一化后共同优化。
融合后重新检查每面重投影和姿态变化，任何拒绝都保留 RGB 位姿。实现详情见
`project_review_rgbd.md`；它是局部精修，目前不会借助深度重新选择所有 IPPE 分支。

上一帧接受的位姿只用于在相近解之间做连续性选择，不能用平滑强行接受明显更差的解。相邻帧若在短时间内发生不合理的平移或旋转突跳，就拒绝当前帧并清空连续性状态。没有有效观测、重投影超阈值或刚体关系不一致时，状态为 `WARN` 或 `LOST`。

轨迹状态机维护明确的 segment：首次接受、重新捕获或时间间隔超过门限时开始新段。浏览器绘线时只连接同一段的点，避免失锁后重新定位产生一条假的直线。

D455 实时和原始 RGB-D 回放均使用颜色帧设备时间戳驱动跟踪；主机单调时钟仅用于
实时处理帧率。深度和彩色帧的时间戳域须相同，时间差默认不超过 20 ms，重复颜色帧跳过。

## 7. 相对 6DoF 输出

第一帧接受的刚体位姿记为 `T_camera_body_0`，每帧输出：

```text
T_relative = inverse(T_camera_body_0) · T_camera_body_t
```

平移是相对 XYZ（米），旋转转换为连续化四元数 `qx,qy,qz,qw`。显示层对位置和四元数做自适应一阶低通；原始测量仍保留，用于诊断和质量判断。RPY 仅用于可读显示，计算和传输以四元数为主，避免欧拉角万向节锁。

## 8. 实时 3D 可视化

`live_dashboard.py` 启动一个本地 HTTP 服务。后台线程采集 D455、检测 ArUco、计算刚体位姿并发布 JPEG 与 JSON 状态；浏览器轮询 `/state` 和 `/image.jpg`。页面使用 Canvas 绘制 XYZ 空间路径、历史姿态轴和当前大坐标轴：红色 X、绿色 Y、蓝色 Z。拖动旋转视角、滚轮缩放，重置按钮只影响显示原点或相机视角。

## 9. 验证边界

合成闭环测试验证配置校验、联合 PnP、TCP 变换、视频回放和真值误差。真实录制验证检测覆盖率、重叠标定、分段和浏览器可视化。绝对 TCP 或世界坐标仍需要实测 `T_body_tcp`/`T_reference_tcp` 和独立 Vicon、OptiTrack 或机器人参考；当前相对轨迹不代替这些验收。
